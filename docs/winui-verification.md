# Проверка единственного интерфейса Copmuter

Поставляемый интерфейс — `shell/Copmuter.Agent`. Отдельного веб-приложения или
набора нарисованных экранов в сборке нет. `agent/ui` — старый код вне поставки.

## Что изменено

- Одна боковая панель: задачи, журнал, диагностика, настройки. На узком окне
  подписи скрываются, навигация остаётся доступна по иконкам с подсказками.
- Чаты создаются, выбираются, фильтруются и удаляются. Ответ привязан к исходной
  задаче, даже если пользователь переключился на другую. История сохраняется в
  `%LOCALAPPDATA%\Copmuter\workspace.json`.
- Никаких декоративных кнопок голоса/вложений, фиктивных метрик или зелёного
  индикатора «всё работает». Соединение проверяется HTTP-запросом к `/v1/models`.
- Enter отправляет, Shift+Enter добавляет строку, Ctrl+N создаёт задачу.
  Подсказки только заполняют поле. Режим «Только план» вызывает `agent_preview`.
- Настройки сервера и модели передаются воркеру при «Сохранить и применить».
  Применение недоступно во время выполнения. Закрытие окна останавливает задачу
  и завершает дочерний Python-процесс без автоматического перезапуска.
- Настоящий `DesktopAcrylicBackdrop`, а не Mica. Тёмная подложка по умолчанию
  86%; плотность регулируется. При отключённой прозрачности Windows или отсутствии
  поддержки системного эффекта окно остаётся читаемым, но без видимого фона.

## Причина зависаний

`agent_execute` / `agent_run_task` удерживают последовательный mutex ABI.
Прежний UI опрашивал `agent_metrics_json` в UI-потоке каждые 60 мс, блокируя
обработку ввода во время команды. Ответ на подтверждение и отмена также ждали
этот mutex. Теперь UI-таймер только разбирает очередь событий, диагностика
считывается по запросу в фоне, управляющие вызовы используют отдельную защиту
времени жизни рантайма. Ожидание подтверждения активируется до публикации события,
чтобы быстрый ответ не потерялся.

## Автоматические проверки

1. `native/build_linux.sh` и `native/build/agent_tests` — тесты ядра.
2. `native/build/agent_tests --abi-controls` (на Windows `.exe`) — отказ и отмена
   через C ABI во время удержания execution mutex; мгновенный ответ из callback.
   Команда в тесте безопасная, все запросы отклоняются.
3. `python -m unittest discover -s ai/tests` — протокол/логика Python-воркера.
4. `dotnet run --project shell/Copmuter.Tests` — сериализация чатов и настроек,
   INPC-уведомления, чтение журнала при открытом writer, ответы HTTP-проверки модели.
5. Windows Actions: компиляция XAML/C#, запуск **из распакованного ZIP**, затем
   `scripts/test-shell-ui.ps1` через UI Automation. Проверяются новая задача,
   ввод, «только план», отправка, настройки, ползунок, диагностика и журнал.
   Скриншоты настоящего WinUI и результат сохраняются в `Copmuter-ui-check`.

## Что проверять на пользовательском Windows

CI не заменяет проверку акрила на реальном рабочем столе с обоями/другими окнами.
Проверить 100/150/200% DPI, изменение размеров, Tab/Enter, светлые обои и режим
Windows без прозрачности. Убедиться, что модель действительно загружена в LM
Studio перед проверкой сложной задачи. «Стоп» — отмена ещё выполняемой работы,
не откат уже завершённых системных действий.
