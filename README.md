# 🤖 AI Computer Agent

**Универсальный AI-оператор компьютера.** Пользователь говорит обычным языком,
**что хочет получить в результате** — а агент сам понимает задачу, составляет
план, выбирает инструменты, действует, проверяет результат, исправляет ошибки
и докладывает итог.

Это не «AI-чат с 20 командами». Это агентная система, для которой компьютер —
единое пространство средств: файловая система, терминал, процессы, окна,
экран, мышь/клавиатура, браузер, настройки ОС.

```
«Найди все PDF за последний месяц и сложи их в папку по месяцам»
«Открой VS Code, создай проект и запусти его»
«Разберись, почему компьютер тормозит»
«Скачай проект с GitHub, поставь зависимости, запусти и почини»
```

## Что умеет (по категориям инструментов — 84 шт.)

| Категория | Инструменты |
|---|---|
| **Файлы** | чтение (вкл. docx/xlsx/pdf), запись, append, создание, удаление (в корзину + undo), move, copy, glob-поиск, **поиск по содержимому** (текст, docx, pdf), сортировка по месяцам, архивация zip/tar (с защитой от traversal), info |
| **Терминал** | `terminal_run` (stdout/stderr/exit code, таймауты, динамическая оценка опасности команды), `terminal_check` (жёсткий read-only allow-list) |
| **Система** | `system_info`, `disk_usage`, `process_list/top`, `process_kill`, **`diagnose_system`** («почему тормозит»: CPU/RAM/диск + топ + рекомендации), `list_monitors` |
| **Окна** | список, поиск по заголовку, фокус, закрытие, свернуть/развернуть/maximize, move (в т.ч. **на конкретный монитор**), resize, «закрой всё лишнее». Windows — через ctypes (без зависимостей), Linux — xdotool/wmctrl |
| **Экран** | скриншоты всех/конкретного монитора (mss), последним снимком, в headless — синтетический снимок (конвейер работает всегда) |
| **Зрение** | `screen_describe` (VLM понимает экран: окна, кнопки, поля, ошибки, позиции в %), `ocr_image/ocr_file` (tesseract), `image_info`, `image_select_best` |
| **Ввод** | клик/двойной/правый, **drag&drop**, scroll, ввод текста, хоткеи, select-all. Без дисплея — виртуальный журнал действий |
| **Clipboard** | чтение/запись (win32 ctypes / xclip), перенос между приложениями |
| **Браузер** (Playwright) | вкладки, навигация, клик по CSS/text/role-селектору, ввод, **извлечение текста/ссылок/форм/таблиц/JS**, скачивание, загрузка файлов, ожидание (SPA), скриншоты, PDF |
| **Приложения** | запуск по имени (реестр + PATH + типичные пути Windows + `start`), понимает русские названия («блокнот», «браузер»), **`open_url`** — ссылка/сайт в системном браузере без Playwright, открытие файла, список установленных, закрытие |
| **Настройки ОС** | звук (get/set/mute), Wi-Fi (status/on/off), Bluetooth, яркость, микрофон, автозагрузка, службы — per-OS шаблоны; критичные — только с подтверждением |
| **Git** | clone, status, log, diff, commit, branch, push |
| **Мета** | `ask_user` (пауза до ответа), `wait`, `undo_last`, `notify_user`, `finish_task` |

## Агентный цикл (сердце системы)

```
цель → ПЛАН (LLM, JSON) →
┌────────────────────────────────────────────┐
│ решение: что делать (function calling)     │
│   → проверка безопасности (риск + режим)   │
│   → [подтверждение пользователя, если надо]│
│   → ВЫПОЛНЕНИЕ инструмента                 │
│   → НАБЛЮДЕНИЕ (результат в контекст)      │
│   → журнал + undo-план                     │
│   → периодическая ПРОВЕРКА ПРОГРЕССА (LLM) │
│   → ошибка? анализ → ДРУГОЙ путь           │
│     (повторы одного действия ограничены,   │
│      перепланирование, ask_user)           │
└────────────────────────────────────────────┘
→ ФАКТИЧЕСКАЯ проверка результата → отчёт
```

Задача **не считается выполненной** по «последний шаг отработал», а по оценке
проверки: LLM отвечает `{progress, achieved, remaining}` на вопрос «достигнута
ли цель». Если LLM хочет завершить, а проверка говорит «нет» — цикл
продолжается. Повторение одного и того же действия ≥3 раз — принудительная смена
стратегии/перепланирование.

## Режимы работы

| Режим | Поведение |
|---|---|
| `auto` | «Сделай всё сам»: работает автономно, подтверждает только критичное и массовые операции |
| `confirm` | Подтверждение действий от среднего риска (по умолчанию) |
| `step` | Подтверждение **каждого** действия |
| `observe` | Автономно, но UI показывает всё вживую (подсветка действий, экран, шаги) |
| `plan_only` | Только план — ничего не выполняется |

## Безопасность и undo

- У каждого инструмента базовый уровень риска (`none/low/medium/high/critical`)
  + **динамическая оценка по аргументам**: `rm -rf /` → critical, `pip install`
  → medium, массовое удаление (>10 элементов или glob) → high, системный
  процесс → critical и т.д.
- Опасные паттерны команд (mkfs, format, reg delete, drop table, curl|sh, ...)
  эскалируются автоматически.
- Удаление — **в корзину агента**; запись — с бэкапом; move/copy/organize —
  с undo-планом. `undo_last` / «отмени последние изменения» / кнопка ↩ в UI.
- Журнал всех действий — на диске, просматриваемый.

## Память

- **Сессия**: цель, план, шаги, наблюдения — checkpoint после каждого шага
  (задачу можно возобновить после перезапуска).
- **Долговременная**: предпочтения («проекты храню в ~/Projects») и факты;
  релевантные пункты автоматически попадают в контекст; UI: просмотр и удаление.

## Задачи: очередь, фон, расписание, триггеры

- **Очередь**: «вот 20 задач — выполняй по очереди» (стек/текст-в-строку в UI и CLI);
  состояние каждой сохраняется.
- **Фоновые**: «скачивай и сообщи когда закончится» — задача уходит в фон,
  агент и UI продолжают работать, результат приходит событием.
- **Расписание**: `daily 09:00`, `weekly mon 09:00`, `hourly`, `every 30m`
  — «каждый день в 9 проверяй сайт».
- **Триггеры**: «когда в Downloads появится PDF — переименуй и перенеси в
  Documents» — наблюдение за папками (polling 3с + watchdog, если установлен).
- **Живое управление**: пауза / продолжить / стоп / убрать из очереди /
  изменить инструкцию (просто отправьте новую задачу).

## Интерфейсы

1. **Web-чат** (основной): `python main.py --web` — аккуратный чат в стиле
   современных мессенджеров:
   - **Система чатов** слева: создание, клик для открытия, переименование
     (двойной клик по названию), удаление, поиск по чатам.
   - **Два режима ответа** (переключатель в шапке):
     - **Чат** — прямой разговор с моделью, ответы **стримятся токенами**
       (минимальная задержка до первого символа);
     - **Агент** — полный агентный цикл: план → инструменты → проверка →
       итог; ход выполнения виден прямо в чате («активности»), итог —
       сообщением ассистента.
   - **Голосовой ввод** (🎤 / `Ctrl+Shift+M`): браузерное распознавание
     (Chrome/Edge, живой текст в поле) или локальный Whisper (двойной клик).
   - **Файлы**: прикрепляйте изображения (уходят в VL-модель), тексты/код
     (содержимое попадает в контекст), любые другие файлы (доступны агенту).
   - Markdown в ответах: заголовки, списки, код-блоки с копированием.
   - Размышления `<think>…</think>` показываются отдельным сворачиваемым
     блоком (для thinking-моделей).
   - Всё «операторское» (режимы риска, память, расписание, триггеры, журнал,
     undo, статистика) убрано в ⚙ **Настройки**, интерфейс не перегружен.
2. **CLI REPL**: `python main.py` — все команды: `/mode`, `/undo`, `/tasks`,
   `/sched`, `/trig`, `/memory`, `/confirm`, `/answer`, ... + особые фразы
   «стоп», «пауза», «продолжай», «отмени».
3. **Одна задача**: `python main.py "Создай папку X" [--mode auto] [--plan]`.

Голос с сервера (СТТ) — опциональный модуль `faster-whisper` (локально).

## Установка

**Ядро работает без единой внешней зависимости** (Python ≥ 3.10, только
stdlib). Всё «железное» подключается опционально и система деградирует
gracefully: недоступный инструмент возвращает наблюдение, агент выбирает
другой путь.

```bash
# минимум — уже можно работать (терминал, файлы, git, браузер-заглушка):
pip install -e .            # или просто: python main.py

# рекомендуемый набор:
pip install mss psutil pypdf pillow
pip install playwright && playwright install chromium   # браузер
# OCR:
sudo apt install tesseract-ocr tesseract-ocr-rus && pip install pytesseract
# голос:
pip install faster-whisper sounddevice
# TUI (опционально):
pip install textual rich
```

### Подключение LLM

Любой **OpenAI-совместимый** API (OpenAI, Groq, OpenRouter, DeepSeek,
Ollama, LM Studio, ...). По умолчанию config.json настроен на **LM Studio**
(`http://localhost:1234/v1`, модель `qwen3-vl-8b-instruct` —
[Qwen3-VL-8B-Instruct-GGUF](https://huggingface.co/lmstudio-community/Qwen3-VL-8B-Instruct-GGUF)):
загрузите модель, включите Developer → Start Server — и всё работает,
ключ не нужен. Список моделей подтягивается кнопкой «Обновить» в ⚙ Настройках.

```bash
export OPENAI_API_KEY=sk-...
# и/или config.json:
{ "llm": { "base_url": "https://api.openai.com/v1", "model": "gpt-4o" } }
# Ollama:
{ "llm": { "base_url": "http://localhost:11434/v1", "model": "llama3.1" } }
```

Для моделей **без function calling** (`"supports_tool_calling": false`) клиент
сам переключается на JSON-протокол действий. **Без API-ключа** система
запускается с `mock`-LLM: детерминированные сценарии для демо и тестов
(весь конвейер работает вживую, офлайн).

### Вариант А — запустить без сборки (нужен только Python 3.10+)

Двойной клик по **`start.bat`** (Windows) или:

```bash
python desktop.py
```

Открывается **нативное окно** приложения (pywebview: на Windows — WebView2,
на Linux — WebKitGTK, на macOS — WKWebView). Если pywebview не установлен —
окно откроется в системном браузере, функционал тот же.

### Вариант Б — собрать один EXE-файл (Windows)

1. Установите Python 3.10+ с [python.org](https://www.python.org/downloads/)
   (галочка **«Add Python to PATH»!**).
2. Двойной клик по **`build_windows.bat`**.

Скрипт сам установит зависимости (pywebview, PyInstaller, mss, psutil,
pypdf, Chromium для управляемого браузера), соберёт всё в
**`dist\AIComputerAgent.exe`** — один самодостаточный файл (~30–200 МБ
в зависимости от установленных опциональных модулей). Переносите EXE на
любой Windows-ПК — ничего дополнительно ставить не нужно.

> ⚠️ EXE собирается только на Windows (PyInstaller не пересобирает между
> ОС-ми). На macOS/Linux аналог: `pip install pywebview && python desktop.py`
> или `pyinstaller ai_agent.spec`.

## Если агент «отвечает, но ничего не делает»

Агент действует **только через вызовы инструментов**. Если модель вместо
вызова пишет текст («Сейчас создам папку…»), цикл не считает это выполнением:
он до 4 раз требует вызвать инструмент, а затем честно завершает задачу
с ошибкой и объяснением. Что проверить в таком случае:

1. **⚙ Настройки → «Проверить связь»** — сервер модели должен отвечать.
   Без сервера агент сразу сообщает об этом (не «зависает» на повторах).
2. **function calling включён**, а модель его поддерживает (LM Studio:
   Qwen3 / Qwen2.5-Instruct, Llama 3.x, Mistral). Если сервер не принимает
   `tools` — выключите галочку: агент перейдёт на **JSON-протокол**
   (`{"tool": "...", "args": {...}}`) и продолжит работать.
3. **Контекст модели ≥ 8k токенов.** Модели за ход уходит релевантный набор
   инструментов (по умолчанию `agent.tools_budget = 40`, ≈5k токенов):
   ядро (файлы, терминал, приложения, finish/ask) + подобранные по ключевым
   словам задачи. `0` — отправлять все; `25` — для моделей с окном 4k.
4. Пути «рабочий стол / Desktop / Документы» разворачиваются в реальные папки
   пользователя (в т.ч. перенесённые в OneDrive на Windows).

## Честные ограничения

- **GUI-действия** (мышь, окна, скриншоты) требуют машины с дисплеем; в
  headless-режиме эти инструменты возвращают внятное наблюдение, и агент
  переключается на прямые средства (или в виртуальный режим с журналом).
- **Окна Linux** — через xdotool/wmctrl (установите их).
- Массовое удаление, финансы, необратимые операции — всегда через
  подтверждение (в режиме `auto` — критичные и массовые).
- Браузерные сценарии с 2FA/кодами — агент остановится и спросит код
  (`ask_user`) — это по дизайну.
