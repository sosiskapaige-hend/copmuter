# Copmuter — локальный агент, который управляет компьютером

Пользователь говорит обычным языком, что нужно получить, — агент сам решает, как это
сделать: мгновенно выполняет простое, планирует сложное, проверяет результат и честно
сообщает, если что-то не вышло.

**Три слоя, как и требует задача:**

| Слой | Технология | Роль |
|---|---|---|
| Оболочка | **C# + .NET 8 + WinUI 3** (`shell/`) | окно, чат, статусы, настройки, поток событий. Никаких низкоуровневых вызовов |
| Ядро | **C++20 → `AgentRuntime.dll`** (`native/`) | рефлексы и руки: маршрутизатор, реестр приложений, оптимизатор, Win32/Shell/процессы/окна/ввод/файлы/PowerShell/скриншоты/проверка/восстановление. Постоянно в памяти |
| Мозг | **Python + Qwen3-VL-8B через LM Studio** (`ai/`) | планирование, рассуждение, код, зрение, контекст, память. Постоянный воркер, поднимается один раз за сессию |

```
ПОЛЬЗОВАТЕЛЬ → FAST ROUTER (C++, микросекунды)
                 ├── простое → нативный инструмент → ПРОВЕРКА → РЕЗУЛЬТАТ       (модель не вызывается)
                 └── сложное → Python/Qwen3-VL → план → инструменты ядра → проверка → переплан
```

Принцип: **LLM — мозг, C++ Runtime — руки, Vision — глаза, Router — рефлексы,
Verification — контроль результата.** Модель не управляет каждым кликом: клики, окна,
файлы и оболочка — это нативные вызовы, а не «подумай и нажми».

---

## Что происходит с простой командой

```
$ agent_host "открой телегу"                       # Windows: Explorer/протокол/реестр
{"ok":true,"route":"direct","action":"launch_app","ms":18,"route_us":42}

$ agent_host "удали папку 123 с рабочего стола"    # найти → (подтверждение) → удалить → проверить
$ agent_host "найди видео про котиков"             # youtube.com/results?search_query=котиков
```

Маршрут выбирается за **~11 мкс** (20 000 прогонов, warm), модель на этих путях не
поднимается вовсе. Сложные задачи уходят в агентный цикл: план модели → вызовы
инструментов ядра → наблюдения → переплан.

## Быстрый старт (Windows)

```bat
:: 1. Ядро
native\build_windows.bat
:: 2. Оболочка
dotnet build shell\Copmuter.Agent\Copmuter.Agent.csproj -c Release
:: 3. Модель
::    LM Studio → загрузить Qwen3-VL-8B-Instruct → Start Server (http://127.0.0.1:1234)
:: 4. Запуск
start.bat
```

Ядро без UI (отладка и скрипты):

```bat
native\build\agent_host.exe "открой vs code"
native\build\agent_host.exe --preview "удали папку 123 с рабочего стола"   :: PLAN ONLY
native\build\agent_host.exe --ai \\.\pipe\agent_ai_v1 --task "напиши калькулятор на python"
native\build\agent_host.exe --metrics
```

## Быстрый старт (Linux/macOS — разработка и тесты)

Ядро логики собирается и тестируется где угодно: платформенный слой подменяется
честной Linux-реализацией (`platform_linux.cpp`), никаких фальшивых успехов —
если команды нет в PATH, будет «команда не найдена».

```bash
native/build_linux.sh --run          # сборка + тесты + бенчмарк маршрутизатора
python3 -m unittest discover -s ai/tests -p 'test_*.py'
```

## Тесты

| Набор | Что проверяет | Команда |
|---|---|---|
| `native/build/agent_tests` — **124 теста** | разбор фраз, маршрутизация, реестр и оптимизатор, пакеты действий, ожидания, полный цикл простой команды, **агентный цикл через настоящий Python-воркер**, честность отказов, ABI, IPC, бенчмарк | `native/build_linux.sh --run` |
| `ai/tests` — **29 тестов** | план и вызовы инструментов, защита от циклов, контекст-бюджет, память, зрение и координаты, протокол канала, сервер воркера | `python3 -m unittest discover -s ai/tests -p 'test_*.py'` |
| `tests/` — 84 теста | прежняя Python-реализация (осталась как справочник, см. ниже) | `python3 -m unittest discover -s tests -p 'test_*.py'` |

Агентный цикл покрыт end-to-end без модели: `ai/fake_brain.py` (сценарный план) и
`ai/dev_scripted.py` (настоящий воркер с подменённым клиентом) — тест запускает их как
процесс, ядро реально создаёт папки и файлы и проверяет результат на диске.

## Устройство репозитория

```
native/     ядро C++20: router, intent, registry, optimizer, batch, execute, wait,
            tool_call, agent_loop, abi, platform_win32/platform_linux, ipc (Named Pipes/Unix)
ai/         Python-мозг: worker (plan/chat/code/vision/compress), llm (LM Studio),
            context (бюджет контекста), memory (SQLite), vision, protocol, prompts
shell/      C# WinUI 3: окно, чат, статусы, настройки, P/Invoke к AgentRuntime.dll,
            надзор за Python-воркером
agent/      ПРЕЖНЯЯ реализация (Python, 133 инструмента). Осталась для справки и
            переноса идей; новая архитектура её не использует
docs:       ARCHITECTURE.md — подробное описание слоёв, протоколов и решений
```

## Лицензия и требования

Windows 10/11 x64, .NET 8 SDK, MSVC (Build Tools), Python 3.10+, LM Studio с моделью
Qwen3-VL-8B-Instruct. Всё локально: облако не требуется.
